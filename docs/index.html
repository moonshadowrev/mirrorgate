Mirror any site on your own domain.

آینه‌ی هر سایت، روی دامنه‌ی خودتان.

MirrorGate is a PHP reverse-proxy mirror for shared hosting. Upload it, set two URLs in .env, and your domain serves a cached, rewritten copy of a remote origin, whatever stack that origin runs.

MirrorGate یک برنامه‌ی PHP برای هاست اشتراکی است که مثل یک CDN کوچک جلوی سایت مبدأ می‌نشیند. آن را آپلود کنید، دو نشانی را در .env بنویسید و دامنه‌تان نسخه‌ی کش‌شده و بازنویسی‌شده‌ی سایت مبدأ را نشان می‌دهد، مهم نیست مبدأ با چه فناوری ساخته شده باشد.

Why MirrorGate

چرا MirrorGate

Your site lives on origin A (say overlord.team). You want the same site under a second domain B (say ormantek.com) on a hosting plan that gives you PHP, FTP and a file manager, and nothing else. No root, no DNS control, no Nginx.

سایت شما روی مبدأ A (مثلاً overlord.team) اجرا می‌شود و می‌خواهید همان سایت روی دامنه‌ی دوم B (مثلاً ormantek.com) هم باز شود. اما هاست شما فقط PHP، FTP و فایل‌منیجر دارد: نه دسترسی روت، نه کنترل DNS، نه Nginx.

1

Configuration only

No code to edit. Two required variables, safe defaults for everything else, and a self check that tells you what is wrong.

فقط پیکربندی

لازم نیست کدی را ویرایش کنید. دو متغیر الزامی دارد، بقیه مقدار پیش‌فرض امن دارند و دستور بررسی به شما می‌گوید چه چیزی اشتباه است.

2

Upload-only friendly

Its own PSR-4 autoloader and .env parser. No Composer on the server, no build step. Needs only curl, json and mbstring.

مناسب هاست آپلودی

اتولودر و پارسر .env خودش را دارد. روی سرور به Composer و مرحله‌ی build نیاز نیست و فقط به افزونه‌های curl، json و mbstring احتیاج دارد.

3

Fails gracefully

Origin down, slow or misconfigured? Visitors get a stale cached copy or a clear error page, never a stack trace or your origin address.

خطا را مرتب مدیریت می‌کند

مبدأ از کار افتاده یا کند است؟ بازدیدکننده نسخه‌ی کش‌شده یا یک صفحه‌ی خطای روشن می‌بیند، نه جزئیات فنی و نه نشانی مبدأ.

Architecture

معماری

A front controller in public/index.php validates the request, consults a file cache, fetches from the origin through an SSRF-guarded client, rewrites the response and emits it. Long-lived protocols are handled by an optional daemon on a host that can run one.

کنترلر ورودی در public/index.php درخواست را اعتبارسنجی می‌کند، کش فایلی را می‌بیند، در صورت نیاز از مبدأ (با کلاینتی که در برابر SSRF محافظت شده) پاسخ می‌گیرد، آن را بازنویسی می‌کند و برمی‌گرداند. پروتکل‌های بلندمدت به عهده‌ی یک دیمون اختیاری است که باید روی میزبانی اجرا شود که اجازه‌ی پردازش دائمی می‌دهد.

  1. Validate. Host, size, method, smuggling checks.اعتبارسنجی. هاست، اندازه، متد و بررسی قاچاق درخواست.
  2. Cache. Fresh hit, or stale while revalidating.کش. نسخه‌ی تازه یا کهنه در حین به‌روزرسانی.
  3. Fetch. Pinned DNS, no redirects followed.دریافت. DNS ثابت‌شده و بدون دنبال‌کردن ریدایرکت.
  4. Rewrite. Origin host becomes mirror host.بازنویسی. نشانی مبدأ به نشانی آینه تبدیل می‌شود.
  5. Serve. Or stale copy / error page on failure.ارائه. یا نسخه‌ی کهنه و صفحه‌ی خطا هنگام شکست.

قابلیت‌ها، با تفکیک صادقانه‌ی محل اجرا

Shared hosting runs PHP in short-lived request workers. Anything needing a long-lived socket requires the daemon on a VPS or any host where you can start a process.

هاست اشتراکی PHP را فقط در پردازه‌های کوتاه‌مدت اجرا می‌کند. هر چیزی که سوکت پایدار لازم دارد، به دیمون روی VPS یا میزبانی نیاز دارد که اجازه‌ی اجرای پردازه‌ی دائمی بدهد.

Quick start in 5 steps

شروع سریع در ۵ گام

Requires PHP 8.3 or newer with ext-curl, ext-json and ext-mbstring. No Composer, and no SSH needed for the web app.

به PHP نسخه‌ی ۸٫۳ یا بالاتر با افزونه‌های ext-curl، ext-json و ext-mbstring نیاز دارید. به Composer احتیاجی نیست و برای خود برنامه‌ی وب SSH هم لازم نیست.

  1. Upload

    Upload the project to your account, for example ~/mirrors/ormantek.com/.

    آپلود

    پروژه را روی حساب هاست آپلود کنید، مثلاً در ~/mirrors/ormantek.com/.

  2. Point the docroot at public/

    Set the domain's document root to the public folder in your control panel. If the panel cannot, use the root shim with the self-protecting .env.php form described in .env.example.

    ریشه‌ی دامنه را روی public/ بگذارید

    در کنترل‌پنل، Document Root دامنه را روی پوشه‌ی public تنظیم کنید. اگر پنل اجازه نمی‌دهد، از فایل ریشه‌ی index.php و حالت خودمحافظ .env.php استفاده کنید که در .env.example توضیح داده شده است.

  3. Create .env one level above public/

    Only two values are required.

    فایل .env را یک سطح بالاتر از public/ بسازید

    فقط دو مقدار الزامی است.

    shell
    cp .env.example .env
ORIGIN_URL=https://overlord.team
MIRROR_URL=https://ormantek.com

  4. Check the setup

    With SSH run the command below. Without SSH, enable the admin with a random 32+ character ADMIN_TOKEN, call /__mirrorgate/check with Authorization: Bearer ..., then disable it again if you do not need it.

    وضعیت نصب را بررسی کنید

    اگر SSH دارید دستور زیر را اجرا کنید. بدون SSH، بخش مدیریت را با یک ADMIN_TOKEN تصادفی دست‌کم ۳۲ نویسه‌ای روشن کنید، آدرس /__mirrorgate/check را با هدر Authorization: Bearer ... صدا بزنید و بعد در صورت نیاز دوباره خاموشش کنید.

    shell
    php bin/mirrorgate check --network

  5. Point DNS and TLS, then open the mirror

    Point the mirror domain at the hosting account, issue a certificate (AutoSSL or Let's Encrypt) and visit https://ormantek.com/.

    DNS و TLS را تنظیم و آینه را باز کنید

    دامنه‌ی آینه را به حساب هاست وصل کنید، گواهی TLS بگیرید (AutoSSL یا Let's Encrypt) و https://ormantek.com/ را باز کنید.

Several sites on one account

چند سایت روی یک حساب

One instance serves exactly one mirror (sub)domain: its own docroot, .env, cache and limits. Instances never share state.

هر نمونه دقیقاً یک (زیر)دامنه‌ی آینه را سرو می‌کند و docroot، فایل .env، کش و محدودیت‌های جدا دارد. نمونه‌ها هیچ وضعیتی را با هم شریک نیستند.

layout
# ~/mirrors/ormantek.com/.env
ORIGIN_URL=https://overlord.team
MIRROR_URL=https://ormantek.com
HOST_MAP=api.overlord.team=api.ormantek.com

# ~/mirrors/api.ormantek.com/.env
ORIGIN_URL=https://api.overlord.team
MIRROR_URL=https://api.ormantek.com
HOST_MAP=overlord.team=ormantek.com

Keep HOST_MAP reciprocal and choose COOKIE_DOMAIN_MODE deliberately. You can also keep one copy of the code and give each subdomain a small index.php stub that points at its own .env.

مقدار HOST_MAP را دوطرفه نگه دارید و COOKIE_DOMAIN_MODE را آگاهانه انتخاب کنید. می‌توانید فقط یک نسخه از کد داشته باشید و برای هر زیردامنه یک فایل کوچک index.php بگذارید که به .env همان نمونه اشاره کند.

پیکربندی

همه‌چیز متغیر محیطی است و اگر متغیری هم‌نام در محیط پردازه تعریف شده باشد، بر فایل ارجحیت دارد. فایل .env.example همه‌ی گزینه‌ها را دارد و دستور php bin/mirrorgate config:dump پیکربندی نهایی را با ماسک‌شدن رازها نشان می‌دهد.

Security first

امنیت در اولویت

SSRF

Upstream URL comes only from configuration. Every DNS answer is checked against private and reserved ranges, the validated IP is pinned, redirects are never followed, and TLS verification cannot be turned off.

نشانی مبدأ فقط از پیکربندی ساخته می‌شود. هر پاسخ DNS با بازه‌های خصوصی و رزروشده مقایسه می‌شود، IP تأییدشده ثابت می‌ماند، ریدایرکت دنبال نمی‌شود و تأیید TLS را نمی‌توان خاموش کرد.

Host header attacks

حمله از راه هدر Host

An unknown Host gets 421. Mirror URLs are built from configuration, never from Host or X-Forwarded-*.

هاست ناشناس پاسخ 421 می‌گیرد. نشانی آینه فقط از پیکربندی ساخته می‌شود، نه از Host یا X-Forwarded-*.

CRLF and request smuggling

تزریق CRLF و قاچاق درخواست

Control characters and bad header names are rejected. Content-Length with Transfer-Encoding, duplicate lengths and odd encodings fail with 400 or 501.

نویسه‌های کنترلی و نام هدر نامعتبر رد می‌شوند. ترکیب Content-Length با Transfer-Encoding، طول‌های تکراری و کدگذاری‌های غیرعادی با ۴۰۰ یا ۵۰۱ رد می‌شوند.

Cache poisoning and traversal

مسموم‌سازی کش و پیمایش مسیر

Keys use normalized path, query and Vary. Cache files are addressed by sha256, never by request path. Dot segments, encoded slashes and NUL are rejected.

کلید کش از مسیر نرمال‌شده، کوئری و Vary ساخته می‌شود. فایل‌های کش با sha256 نام‌گذاری می‌شوند، نه با مسیر درخواست. نقطه‌بخش‌ها، اسلش کدشده و NUL رد می‌شوند.

Open redirect and XSS

ریدایرکت باز و XSS

Redirects are rewritten against a strict host map and a leading // is collapsed. Rewriting replaces host literals only and never injects markup.

ریدایرکت‌ها بر پایه‌ی یک نگاشت سخت‌گیرانه بازنویسی می‌شوند و // ابتدای مسیر به یک اسلش تبدیل می‌شود. بازنویسی فقط نشانی‌ها را جایگزین می‌کند و هیچ نشانه‌گذاری‌ای تزریق نمی‌کند.

Admin and DoS

مدیریت و DoS

Admin is off by default, uses a constant-time token check with lockout and an optional IP allowlist. Limits cover body size, URL, headers, timeouts, concurrency, streams and rate.

بخش مدیریت پیش‌فرض خاموش است، توکن را با مقایسه‌ی زمان‌ثابت بررسی می‌کند، قفل پس از تلاش‌های ناموفق دارد و فهرست مجاز IP اختیاری است. محدودیت‌ها شامل اندازه‌ی بدنه، نشانی، هدرها، زمان‌ها، هم‌زمانی، جریان و نرخ می‌شوند.

No leaks

بدون نشت اطلاعات

.env must live outside the docroot or use the self-protecting form, otherwise boot fails closed. Error pages and admin output never show the origin address, paths or stack traces.

فایل .env باید بیرون از docroot باشد یا از حالت خودمحافظ استفاده کند، وگرنه اجرا متوقف می‌شود. صفحه‌های خطا و خروجی مدیریت هرگز نشانی مبدأ، مسیرها یا stack trace را نشان نمی‌دهند.

What it cannot do

چه کارهایی از آن برنمی‌آید

It cannot protect visitors from a malicious origin, and it is not a WAF or an anonymizer. Report vulnerabilities privately through the security policy.

نمی‌تواند بازدیدکننده را از یک مبدأ مخرب محافظت کند و نه WAF است و نه ابزار گمنامی. آسیب‌پذیری‌ها را از مسیر خط‌مشی امنیتی و به‌صورت خصوصی گزارش کنید.

Limitations

محدودیت‌ها

  • WebSocket, gRPC, TCP and UDP need bin/mirrorgate-daemon on a host that allows a long-lived process.
  • SSE holds one PHP worker per open stream and is capped. Buffering hosts delay events.
  • No wildcard subdomain mirroring: one instance and an explicit HOST_MAP per host.
  • Prefix mode merges origin hosts into one browser origin and needs an explicit acknowledgement.
  • JavaScript rewriting is literal replacement. Computed or obfuscated hosts are not rewritten.
  • React Server Component streams are not rewritten by default.
  • Cache size is bounded by your account's disk and inode quota.
  • Not a WAF and not an anonymizer.
  • WebSocket، gRPC، TCP و UDP به bin/mirrorgate-daemon روی میزبانی نیاز دارند که پردازه‌ی دائمی را مجاز بداند.
  • SSE به‌ازای هر جریان باز یک پردازه‌ی PHP را اشغال می‌کند و سقف دارد. در هاست‌های بافرکننده، رویدادها با تأخیر می‌رسند.
  • آینه‌ی ستاره‌ای زیردامنه‌ها پشتیبانی نمی‌شود؛ برای هر هاست یک نمونه و یک HOST_MAP صریح لازم است.
  • حالت prefix چند میزبان مبدأ را در یک origin مرورگر ادغام می‌کند و تأیید صریح می‌خواهد.
  • بازنویسی جاوااسکریپت فقط جایگزینی متنی است و نشانی‌های محاسبه‌شده یا مبهم‌شده را تغییر نمی‌دهد.
  • جریان‌های React Server Components به‌طور پیش‌فرض بازنویسی نمی‌شوند.
  • اندازه‌ی کش به سهمیه‌ی دیسک و inode هاست محدود است.
  • WAF نیست و ابزار گمنامی هم نیست.

FAQ

پرسش‌های پرتکرار

Is mirroring a site legal?آینه‌کردن سایت قانونی است؟

MirrorGate is a tool. Mirroring a site you do not own or have permission for may violate copyright, terms of service or local law. Use it for your own properties, for sites that allow it, or for resilience in front of an origin you operate.

MirrorGate فقط یک ابزار است. آینه‌کردن سایتی که مال شما نیست یا اجازه‌اش را ندارید، ممکن است حق نشر، شرایط استفاده یا قانون محلی را نقض کند. از آن برای دارایی‌های خودتان، سایت‌هایی که اجازه می‌دهند، یا برای پایداری جلوی مبدأی که خودتان اداره می‌کنید استفاده کنید.

Does the origin stack matter?فناوری مبدأ مهم است؟

No. It speaks HTTP and rewrites hosts in common formats. Bundles with hard-coded absolute origin URLs need REWRITE_JS=true; hosts embedded in RSC payloads are a known hard case.

نه. فقط HTTP صحبت می‌کند و نشانی‌ها را در قالب‌های رایج بازنویسی می‌کند. بسته‌هایی که نشانی مطلق مبدأ را در کد نوشته‌اند به REWRITE_JS=true نیاز دارند و نشانی‌های داخل داده‌های RSC هنوز مورد دشوار شناخته‌شده‌اند.

Can users log in through the mirror?کاربران می‌توانند از طریق آینه وارد حساب شوند؟

Cookies are forwarded and rewritten. Anyone who operates the mirror can read what passes through it, so never enter credentials on a mirror you do not control.

کوکی‌ها ارسال و بازنویسی می‌شوند. اما هر کس آینه را اداره کند می‌تواند ترافیک عبوری را ببیند؛ پس هرگز روی آینه‌ای که خودتان کنترل نمی‌کنید رمز عبور وارد نکنید.

Does it hide my origin?مبدأ من پنهان می‌ماند؟

It does not claim to. Headers and error pages never leak origin details, but the hostname still appears in DNS history, certificates and anything the origin embeds itself.

چنین ادعایی ندارد. هدرها و صفحه‌های خطا جزئیات مبدأ را فاش نمی‌کنند، اما نام میزبان همچنان در تاریخچه‌ی DNS، گواهی‌ها و هر چیزی که خود مبدأ درج می‌کند دیده می‌شود.

Why not Cloudflare or Nginx?چرا Cloudflare یا Nginx نه؟

If you control DNS or a server, use them; they do this better. MirrorGate is for accounts where PHP and a file manager are all you have.

اگر DNS یا سرور را در اختیار دارید از همان‌ها استفاده کنید، چون این کار را بهتر انجام می‌دهند. MirrorGate برای حساب‌هایی است که فقط PHP و فایل‌منیجر دارند.

How do I clear the cache?کش را چطور پاک کنم؟

php bin/mirrorgate purge --all, or --prefix=/blog, or --url=/path. The authenticated admin purge endpoint does the same over HTTP.

با php bin/mirrorgate purge --all یا گزینه‌های --prefix=/blog و --url=/path. نقطه‌ی پاک‌سازی بخش مدیریت هم همین کار را از راه HTTP و با احراز هویت انجام می‌دهد.

Which PHP versions?با کدام نسخه‌های PHP کار می‌کند؟

PHP 8.3 minimum. The code avoids deprecated APIs, dynamic properties and implicit nullable types, so it is written to run clean on 8.4 and 8.5.

حداقل PHP 8.3. کد از API های منسوخ، ویژگی‌های پویا و نوع‌های nullable ضمنی دوری می‌کند تا روی نسخه‌های 8.4 و 8.5 هم بدون هشدار اجرا شود.
